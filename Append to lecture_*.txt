
### Component Details

1. **Audio Callback Stream (`sd.InputStream`)**:
   - Captures continuous `float32` PCM audio chunks (block size 1024) from the loopback audio device.
   - Duplicates incoming audio blocks onto two independent thread-safe queues (`recording_queue` and `transcription_queue`).

2. **Continuous Audio Recording Thread (`audio_recorder`)**:
   - Runs in parallel to consume audio buffers from `recording_queue`.
   - Normalizes and clips `float32` sample values (`-1.0` to `1.0`) to 16-bit signed integer PCM format (`np.int16`).
   - Writes directly to disk using `wave.open` (`.wav` format) in real-time.

3. **Pre-Loaded Whisper Inference Engine (`transcription_worker_with_model`)**:
   - Pre-loads the selected Whisper model into memory **before** initiating audio stream capture, eliminating initial latency gaps.
   - Accumulates stereo input audio in a floating-point NumPy buffer array.
   - Applies a sliding-window algorithm using configurable parameters (`CHUNK_SECONDS` and `OVERLAP_SECONDS`).
   - Downmixes stereo audio buffers to single-channel (mono) by averaging left and right channels (`np.mean(chunk, axis=1)`).
   - Invokes `model.transcribe()` with explicit settings (`language="en"`, `fp16=False`, `temperature=0`, `condition_on_previous_text=True`).

4. **Instant File Flushing & Cleanup**:
   - Appends transcript lines formatted as `[HH:MM:SS] <text>` directly to disk with immediate `f.flush()` calls to guarantee zero data loss if abruptly interrupted.
   - Handles `KeyboardInterrupt` (`Ctrl+C`) gracefully by shutting down stream ingestion, passing `None` sentinels to signal both worker threads, waiting for queue drains via `.join()`, and appending session summary footers.
